# ELF: Deployment & Security Model

This guide covers deploying the Efficient Log Forwarder agent at scale in an
enterprise environment: as a least-privilege Windows service installed via
the server-generated PowerShell script (also suitable for GPO/SCCM fleets as
a computer-startup script), with the security hardening the service
conversion provides.

---

## 1. Security model

The agent is designed to run with the **minimum privileges** needed to do its
job: read the Windows Event Log and send events to the management server.

| Concern | Design |
|---------|--------|
| **Runs as** | A dedicated local user `ELFAgent`, **not** Administrator, not LocalSystem. |
| **Rights granted** | `SeServiceLogonRight` (log on as a service), `SeSecurityPrivilege` (read the Security event log), membership in **Event Log Readers** (built-in group with read access to all event logs). |
| **Install location** | `Program Files\ELFAgent\`, read-only for normal users (default Program Files ACL). Contains the exe + `config.ini` + shipped `rules/` + `lists/`. |
| **State location** | `%ProgramData%\ELFAgent\`, writable by the service account only. Contains `logs\`, `state\bookmarks\`, `spool\`, `rules\` (server-pushed), `lists\` (server-pushed). |
| **Log protection** | The `%ProgramData%\ELFAgent\` tree is ACL'd so only `SYSTEM` and the `ELFAgent` account have access. Normal users cannot read the logs, the spool, or the bookmarks. |
| **Survives reboot** | The service is `SERVICE_AUTO_START`; it starts on boot. |
| **Survives crash** | Recovery actions: restart after 30s, 30s, then 60s. Failure count resets after 1 day. |
| **Survives network outage** | Pending POSTs are spooled to disk (`%ProgramData%\ELFAgent\spool\`) and retried with exponential backoff (1s→60s). Event bookmarks persist per-channel positions so no events are lost across a restart. |
| **Bounded disk use** | Agent log: 1MB × 3 rotated copies (~4MB max). Spool: capped at 100MB (oldest evicted). Both configurable in `config.ini`. |
| **Invisible to users** | No console window, no tray icon, no UI. The service runs in Session 0. |
| **Cannot be killed by normal users** | Service control requires Administrator. The process runs as a different account; a normal user cannot end it via Task Manager. |

## 2. Deployment methods

### 2.1 PowerShell script (ad-hoc / small fleets / GPO / SCCM)

Generated by the management server's **+ Add New Agent** button. Paste into
an elevated PowerShell prompt on the target host, or run the downloaded
`install-elf-agent.ps1`. For a handful of hosts, paste it interactively; for
larger fleets, deploy the downloaded `.ps1` via GPO as a computer-startup
script or via SCCM (it is idempotent; re-running it upgrades in place).

The script:
1. Downloads the exe from the server to `Program Files\ELFAgent\`.
2. Creates the `%ProgramData%\ELFAgent\` state tree.
3. Creates the `ELFAgent` local user with a random 24-char password.
4. Adds it to **Event Log Readers**.
5. ACLs the data dir (SYSTEM + ELFAgent only).
6. Writes `config.ini` (with `agent_id` = the host's computer name).
7. Registers the agent with the server.
8. Creates + starts the service (auto-start, recovery actions).

## 3. Post-install verification

```powershell
# Service is running:
Get-Service ELFAgent
# Expected: Status=Running, StartType=Automatic

# Recovery actions:
sc.exe failure ELFAgent
# Expected: RESET=86400, actions=restart/30000/restart/30000/restart/60000

# Service account:
whoami /user   # (run as the service account to verify its rights)
# Or check the account's group membership:
Get-LocalGroupMember 'Event Log Readers'

# Data dir ACL:
Get-Acl "$env:ProgramData\ELFAgent" | Select-Object -ExpandProperty Access
# Expected: SYSTEM FullControl, ELFAgent FullControl, no others.

# Log file (as admin):
Get-Content "$env:ProgramData\ELFAgent\logs\elf_agent.log" -Tail 20

# Agent registered with server:
# Check the Agents tab in the web UI; the host should appear within 30s.
```

---

## 4. Upgrading

Re-generate the install script from the server (after staging the new exe
into `server/agent/` and redeploying the Docker image). The script detects an
existing service, stops + deletes it, then re-creates it with the new exe.
State is preserved.

---

## 5. Uninstalling

### Cleanup script (recommended)

Use the cleanup `.ps1` generated by the management server (**+ Add New
Agent** modal → Troubleshooting). It removes the service, the local
`ELFAgent` account, LSA rights, and both directories.

### Manual

```powershell
# If the service is stuck in "stopping" (hung agent process), kill the
# process FIRST; the SCM never force-kills a service on its own:
$svcPid = (Get-CimInstance Win32_Service -Filter "Name='ELFAgent'").ProcessId
if ($svcPid -and (Get-Process -Id $svcPid -ErrorAction SilentlyContinue)) {
    Stop-Service ELFAgent -Force -ErrorAction SilentlyContinue
    Start-Sleep -Seconds 5
    if (Get-Process -Id $svcPid -ErrorAction SilentlyContinue) {
        taskkill /F /PID $svcPid
    }
}
sc.exe delete ELFAgent
Remove-LocalUser ELFAgent
Remove-Item -Recurse -Force "C:\Program Files\ELFAgent"
Remove-Item -Recurse -Force "$env:ProgramData\ELFAgent"   # optional
```

## 6. Troubleshooting

### Service won't start
1. Check `sc.exe query ELFAgent` for the last error.
2. Check the Application event log for service start failures.
3. Check `"$env:ProgramData\ELFAgent\logs\error.log"`; the agent logs
   startup errors there even if the service can't stay up.
4. Common cause: the `ELFAgent` account password doesn't match. Re-run the
   installer, or reset the password and update the service:
   ```powershell
   $pw = -join ((65..90)+(97..122)+(48..57) | Get-Random -Count 24 | % {[char]$_})
   $sec = ConvertTo-SecureString $pw -AsPlainText -Force
   Set-LocalUser -Name ELFAgent -Password $sec
   sc.exe config ELFAgent obj= ".\ELFAgent" password= $pw
   Start-Service ELFAgent
   ```

### Agent not reading the Security log
The service account needs `SeSecurityPrivilege` + Event Log Readers membership.
The installer grants both, but if a GPO strips them:
```powershell
net localgroup "Event Log Readers" ELFAgent /add
# SeSecurityPrivilege is granted via Local Security Policy → User Rights
# Assignment → "Manage auditing and security log": add ELFAgent.
```

### Logs are empty
- The default log level is `notice`, which shows only startup/shutdown/alerts.
  Set `level=info` or `level=debug` in `config.ini [logging]` for more detail.
- The log file is at `%ProgramData%\ELFAgent\logs\elf_agent.log`. The install
  script grants `BUILTIN\Administrators` read access to the `logs` subtree
  only (SYSTEM and the service account keep full control of the data tree;
  `spool`, `rules`, `state` stay private), so an elevated prompt can read it
  without `takeown`. If an elevated prompt still gets *Access denied* (a host
  installed by an older script without that grant), re-run the install script
  once, or copy the logs out with `robocopy "$env:ProgramData\ELFAgent\logs"
  <dest> /B` (backup semantics).
- `error.log` holds every ERROR line. The lines worth knowing: `Dropping POST
  ... HTTP 4xx` (a permanently rejected request; `401` means the enrollment
  token was revoked: re-run the install script), `AGENT CRASH` blocks (which
  name the thread and the exception), and `[STATUS] WARNING: events evicted
  before evaluation` (the engine fell behind).

### Spool is full
If the server is down for a long time, the spool caps at `max_spool_mb`
(default 100MB) and starts evicting the oldest entries; each eviction batch is
logged once. Increase the cap in `config.ini [spool] max_spool_mb` if you
expect prolonged outages. Entries are deleted only after the server accepts
them, and a request the server rejects outright (HTTP 4xx) is dropped with a
log line rather than retried forever, so a single bad request never blocks
everything queued behind it.

### Antivirus (Defender) CPU spikes with large rulesets
With 2000+ rules enabled, Windows Defender's real-time scanning
(`MsMpEng.exe` at 100% CPU) hooks the agent's rule-file I/O: every changed
rule file written on a poll is scanned, and every ruleset reload re-reads
every rule file. Exclude the agent's state tree and process:

```powershell
Add-MpPreference -ExclusionPath "$env:ProgramData\ELFAgent"
Add-MpPreference -ExclusionProcess "efficient_log_forwarder.exe"
```

For a fleet, deploy the same exclusions via GPO (*Computer Configuration →
Administrative Templates → Windows Components → Microsoft Defender Antivirus →
Exclusions → Path/Process Exclusions*). The state tree is ACL'd to `SYSTEM` +
the `ELFAgent` service account only, so the exclusion cannot be abused by a
normal user. See `docs/USAGE.md` §12.1 for the full discussion (including a
minimal-exclusion variant).

## 7. File layout reference

```
C:\Program Files\ELFAgent\              (read-only for users)
    efficient_log_forwarder.exe
    config.ini
    rules\                              (shipped defaults)
    lists\

%ProgramData%\ELFAgent\                 (ACL: SYSTEM + ELFAgent only)
    logs\
        elf_agent.log                   (at [logging] level)
        elf_agent.log.1, .2, .3         (rotated)
        error.log                       (ERROR only)
    state\bookmarks\
        <channel>.bookmark.xml          (per-channel resume positions)
    spool\
        *.spool                         (pending POSTs)
    rules\                              (server-pushed)
    lists\                              (server-pushed)
```
